# 桌面版报告引擎同步设计

## 目标

将最新 `报告生成工具V0.1-5.py` 的业务修复完整迁移到桌面仓库 `backend/report_engine.py`，保留桌面版特有的资源定位和重庆无模板生成能力；同时将测试程序和测试产物统一管理。

## 实现范围

1. 以最新 Python 工具为业务逻辑基线，避免逐段手工补丁漏掉两级表头、精简偏差分析、桥隧备注保留、无有效点区段判断、三节区段排序等连续修复。
2. 在同步后的引擎中保留桌面适配：
   - `application_root()` 与 `resource_template_path()`，确保源码和 PyInstaller 模式都从应用根目录读取模板；
   - 重庆模板缺失且 `require_template=False` 时调用 `backend.minimal_docx`；
   - 现有公开入口和 `bridge.py` 调用签名不变。
3. 不修改前端界面、桥接字段和产品交互。
4. 本次不生成或重打 EXE，不推送远程仓库。

## 测试整理

- 唯一测试程序：`tests/test_report_generator.py`。
- 合并桥接测试、重庆无模板测试、广东最新业务回归和最小源码导入检查。
- 删除原 `tests/test_bridge.py`、`tests/test_minimal_docx.py`、`tests/cdp_verify.mjs`，以及 `build-tools` 下仅用于 probe/smoke/窗口测试的脚本。
- 保留真正的构建文件，如图标生成工具、PyInstaller spec 和 `build.bat`。
- 所有测试过程产物统一写入 `tests/artifacts/`；该目录加入 `.gitignore`。测试本身使用临时子目录并负责清理。
- 后续新增测试只扩展 `tests/test_report_generator.py`，不再创建新的测试程序。

## 数据与回归标准

- TDD：先在旧桌面引擎上运行新增广东回归并看到预期失败，再同步业务引擎。
- 统一测试必须覆盖：
  - 桌面资源路径仍指向应用根目录；
  - 重庆无模板报告仍可生成；
  - 广东螺栓对比表两级表头物理格/逻辑格/网格列为 8/10/10，父表头跨度为 2、2；
  - 偏差分析只保留平均偏差与一致性占比；
  - 桥隧备注扫描不丢失 `guardrail_note`；
  - 仅二波或仅三波有数据时只输出对应数据，不出现“无有效检测点位”；二者都无数据且有桥隧标记时才输出该说明；
  - 标线、高度、螺栓共同区段相对顺序一致。
- 运行现有 Python 回归和源码导入验证；真实佛山/珠海数据仅作为端到端回归输入，不复制进仓库。

## 风险控制

- 不直接用最新文件覆盖后就结束；同步后按函数与入口检查桌面差异，防止丢失 `minimal_docx` 和 PyInstaller 路径适配。
- 不提交用户模板、真实 Excel/Word、生成报告、日志或截图。
- 不改依赖，除非实际测试证明最新引擎新增了缺失依赖。
